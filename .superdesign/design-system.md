# DALEELAK native Android reference

Society-sector Jordan government guidance prototype; intended as a future Sanad extension, not an official Sanad integration. Native Kotlin/Compose is the product. Superdesign is only a browser review prototype, never a replacement web app.

User-selected minimalist Navy and Sky. Use primary #1E3A8A, text #0F172A, page #F8FAFC, selected surface #DBEAFE, white cards, secondary text #64748B, outline #E2E8F0. Amber #F59E0B optional only. No purple, gradients, heavy shadows or decorative fonts. Default Android sans, Arabic zero letter spacing. Native spacing 8/12/16/20/24dp, card corners 16–20dp, controls >=48dp. RTL. Phone viewport. No avatar, account, profile collection or fabricated Sanad branding. Identity is the existing text wordmark دليلك with DALEELAK caption; no logo asset exists.

Home: one new-operation action; separate current, finished and history entries with app-owned counts; secondary locations action. Current includes new and ongoing saved operations. Finished is user-reported completion.

Chat: microphone is primary; text replies stay visible; typing/keyboard appears only on demand. Exactly three prompts. Voice controls are labeled pending in this UI build. Later spoken replies default on, with interruption/replay; no fake active recording/audio. AI remains scripted in the current native build.

Journey: general steps are UI cards, not a flowchart. Initial overview combines all ready unfinished tasks, including parallel tasks. One step card fills available page area and snaps vertically; users may scroll forward to upcoming cards without marking them ready. Long cards have internal scrolling. Next/previous buttons make cards accessible without gestures. Categories: documents, actions, payments/commitments, visits. Known formats only. No invented portrait, studio, fee, place, availability or official result.

Native plan is an illustrative layout fixture. Use the exact fixture content when reproducing the UI. A separate neutral example of two simultaneous generic tasks may demonstrate layout only, explicitly labeled fictional; it must never imply an official family-book rule. Prefer preserving native fixture instead of inventing procedure content.

Whole-trip location planning is only a possible improvement. Do not render it as an existing capability. Booking remains labeled local simulation.
